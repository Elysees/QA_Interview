# QA Interview：游戏 QA 面试资料库

本仓库供面试官准备游戏测试、测试开发岗位面试，包含题库、面试模板、评分方案与提问方法。工作流程是：阅读简历和岗位要求，确定考察重点，生成面试材料，执行面试并记录证据。

## 先选岗位流程

| 面试类型 | 使用模板 | 时长 | 主要考察内容 | 评价方式 |
|---|---|---|---|---|
| 游戏功能测试（执行型 / 外包） | [功能测试面试题单模板](./功能测试面试题单模板.md) | 20 分钟 | 简历真实性、测试基础、问题分析、任务理解与表达、责任心 | 按模板记录证据；量化权重、否决线和录用线待定 |
| 测试开发（校招 / 社招） | [测试开发初试报告模板](./测试开发初试报告模板.md) | 50 分钟 | 计算机基础、编程能力、测试基础、项目经验、软实力 | 使用 [评分权重方案](./测试开发岗面试评分权重方案.md)，区分校招和社招 |

生成材料时，岗位标注使用「游戏测试」或「测试开发」。执行型功能测试不安排编程和计算机基础题，也不考察代替负责人作上线决策。

## 开始一次面试准备

### 需要的输入

- 候选人简历。
- 招聘岗位、职责范围和招募类型（校招 / 社招）。
- 功能测试：招聘方的测试范围清单、所选系统的需求规则与配置。
- 测试开发：岗位实际使用语言、候选人主语言及希望核实的项目经历。

缺少信息时，在材料中标出待确认项。简历中的成果是候选人的声称；面试前的推测和风险点不写成已验证事实。模板中的示例数值不能当作招聘方项目的实际配置。

### 游戏功能测试

1. 按测试范围选一个系统作为主场景，把测试点梳理、缺陷定级和任务复述放在同一系统下。
2. 从简历中选出需要核实的具体声称，生成「问题 + 参考要点 + 追问」题单。
3. 按 20 分钟时间表检查题量，明确默认题和备选题；追问和备选题不额外延长面试。
4. 面试后记录候选人原话或具体行为、对应观察和待验证项，由面试官写建议及理由。单题达标不直接等于整场通过。

### 测试开发

1. 根据简历和岗位要求生成候选人画像，拆分经历、个人贡献、优势声称和待验证点。
2. 面试官 review 画像并确定侧重点，再生成面试安排和问题列表。
3. 按经历组织问题组（Cluster），准备实战与概念两条追问路径；主动覆盖计算机基础。
4. 按 50 分钟时间表选题：开场 5 分钟、三个问题组合计 23 分钟、编程 10 分钟、测试场景 4 分钟、软实力 4 分钟、候选人提问 4 分钟。
5. 编程仅选一道适配时段的题，10 分钟包含完成后的追问。候选人题面与面试官参考实现分开。
6. 面试后按评分方案记录五个维度的证据，先核对硬门槛，再计算综合分和判断区间。未考察的维度不能用低分代替，也不能重新分配权重。

题库只提供选题素材，不另设评分权重或录用线。README 提供导航；调整规则时先修改对应来源，再同步其他文档中的摘要和示例。

本次统一保留现有校招、社招权重和录用分数线；社招计算机基础按原方案的「≥ 3」硬门槛执行。原先遗漏的总分区间明确为待补充评估，不视为自动通过。

## 材料保存

产出按**一位候选人一个文件夹**保存到 `outputs/<姓名>/`。同一人的画像、面试报告、编程题面、评分表都放在该文件夹内，文件名使用材料类型，不在 `outputs/` 根目录散放个人材料。完整目录与同名、多轮面试规则见 [产出说明](./outputs/README.md)。

Git 默认只共享通用资料和目录说明：候选人原始资料放在 `inputs/` 或 `resumes/`，实际面试产出放在 `outputs/<姓名>/`，这些内容由 [.gitignore](./.gitignore) 排除。`outputs/README.md` 保留版本管理，不在其中收录实际候选人名单。本机工具配置和临时文件也不提交。
