# 面试产出目录

按岗位模板生成的材料统一采用**一位候选人一个文件夹**。先确定候选人目录，再在其中创建或更新材料，不在 `outputs/` 根目录散放个人文件。

候选人目录及其中的全部材料默认只保留在本机，由 [.gitignore](../.gitignore) 排除；仅本说明文件进入版本管理。本说明使用占位符展示结构，不收录实际候选人名单。

## 目录结构

```text
outputs/
├── README.md
└── <姓名>/
    ├── 候选人画像.md
    ├── 面试报告.md
    ├── 编程题.md
    └── 面试评分表.md
```

上面是测试开发岗的材料结构。功能测试岗通常生成 `面试题列表.md`，同样放在候选人目录中；只创建本次流程需要的材料，不为凑齐结构生成空文件。

## 文件命名

| 材料 | 文件名 | 内容 |
|---|---|---|
| 测开候选人画像 | `outputs/<姓名>/候选人画像.md` | 简历经历拆解、待验证声称、面试侧重点 |
| 测开面试官材料 | `outputs/<姓名>/面试报告.md` | 50 分钟安排、问题与追问、参考实现、观察点；面试后记录回答证据，实际评分链接到评分表 |
| 测开候选人编程题面 | `outputs/<姓名>/编程题.md` | 题目、输入输出、示例、限制；不含答案、考察点或评分提示 |
| 测开评分记录 | `outputs/<姓名>/面试评分表.md` | 记录具体回答、提示程度、各维度分数与理由；面试前保持未考察 |
| 功能测试面试官材料 | `outputs/<姓名>/面试题列表.md` | 20 分钟题单、参考要点和追问；面试后追加观察证据与建议 |

## 同名与多轮面试

- **同一候选人**：复用同一候选人目录。不同人同名时，使用 `outputs/<姓名>-<候选人编号>/` 区分；编号来自已有候选人记录或由面试官明确，不用手机号等联系方式作目录名。不能确定是否为同一人时，先核实再合并。
- **多轮或不同岗位**：仍归在同一个候选人目录下，按 `outputs/<姓名>/<日期>-<轮次>-<岗位>/` 保存各轮材料，例如 `outputs/<姓名>/2026-10-28-初面-测试开发/面试报告.md`。已有文件不得被新一轮结果覆盖；必要时先把旧轮次的相关材料一起归档到对应子目录，再修复链接。
- **同一轮的更新**：在该轮目录内更新对应材料，保留面试日期、材料状态和必要的修订说明，不另建散落在根目录的副本。

## 生成与更新检查

1. 先检查该候选人目录是否存在，确定本次是新候选人、新轮次还是已有材料更新。
2. 所有材料写入同一候选人目录或本轮子目录；同目录互相引用使用相对链接，例如 `./编程题.md`。
3. 引用仓库模板时按实际目录层级计算路径。单轮候选人目录引用评分方案为 `../../测试开发岗面试评分权重方案.md`，增加轮次子目录后层级也相应变化。
4. 调整目录或文件名时，同步修复画像、题单、题面、评分表之间的链接，检查文件完整性与链接可访问性。
5. 确认 `outputs/` 根目录只有通用说明和候选人文件夹，候选人材料仍被 Git 忽略。

每份材料注明岗位、招募类型、面试日期（未排期则写待定）和材料状态（准备中 / 已确认 / 已面试）。面试前的计划和推测、面试后的回答证据与结论分开记录。

测开面试官材料在面试前是安排与题单，不是已完成的评价。没有实际回答证据时，评分和最终建议留空。功能测试暂不生成量化总分。
